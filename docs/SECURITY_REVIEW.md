## 后续 AI 接入的前置条件

独白全文、照片、搜索索引、日志、崩溃信息均不得自动进入 AI。发送必须展示具体选段、服务方和目的，让用户逐次确认；长期记忆需另一份可撤回授权。导入来的 `mode` 字段和历史共鸣状态不能代替新设备/新服务的授权。默认无权限；撤销后停止后续处理并提供记忆查询、纠正、删除机制。

## 仓库防护

- `.gitignore` 排除常见凭据、签名文件、数据库与备份；已跟踪文件不会被 ignore 自动保护。
- `tools/check_repository.py` 检查 Git 索引（含强行加入的文件），对疑似凭据、用户导出、图片载荷、二进制和原型联网能力给出阻止；只输出路径及原因。
- 人工复核每个待提交文件，尤其是注释、测试样本、日志和截图。简单正则无法识别所有自然语言日记或所有凭据格式。
- CI 使用固定版本 checkout、只读权限，不上传测试产物，不读取应用数据；首次上传前仍必须本地检查，CI 在上传后执行，不能撤回已泄漏的信息。
- 未来 Android 的 Gradle Wrapper JAR、产品图片等合法二进制也会被保守阻止；先审核来源和校验值，再以独立 PR 精确调整规则，禁止整体关闭防护。
- 不上传原始 ZIP，也不把私人备份放进仓库目录。private 仓库仅限制访问，不能替代数据最小化和加密。

若日后发现凭据进入历史，应先吊销/轮换，再联系用户制定历史清理方案。当前禁止擅自 force push；删除最新文件并不能删除历史中的秘密。

用户最新授权将检查后的源码、产品文档和开发配置上传至公开仓库 `accding/33333`。仓库可见性选择不改变独白授权边界或真实用户数据的排除要求；本次历史提交也在上传前接受相同检查。
